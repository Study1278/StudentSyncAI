This is the map — whenever you're confused about "why does this project have so many files," come back here.

main.pyEntry point. 🧠 Every core concept you now understand

1. The request-response cycle

Client → HTTP Request → Backend route → Function runs → Response (JSON) → Client

2. Why code is split into files

Separation of concerns: main.py wires things together, database.py owns the DB connection, models.py owns table structure, schemas.py owns API data shape, routers/ group related endpoints.

3. ORM (Object-Relational Mapping)

SQLAlchemy lets you write Python classes instead of raw SQL. class Subject(Base): becomes an actual CREATE TABLE subjects (...) behind the scenes.

4. Dependency Injection

FastAPI runs a function (like get_db or verify_token) automatically before your route code, and hands you the result — no repeated logic in every function.

5. Pydantic schemas & validation

Incoming data is checked against your schemas.py classes before your function runs. Bad data is auto-rejected with a 422 error.

6. Password hashing vs. encryption

  • Encryption is reversible with a key. Hashing (bcrypt) is one-way, permanently.
  • bcrypt salts every password — identical passwords produce different hashes.
  • bcrypt is intentionally slow, making brute-force attacks impractical.
  • "Online decrypters" don't decrypt — they guess-and-check weak passwords.
Never store plain passwords. Ever. In any project, for the rest of your career.

7. JWT (JSON Web Tokens)

  • Format: header.payload.signature — readable by anyone, but tamper-proof because of the server-only secret key.
  • On login: server creates and signs a token containing user_id + role + expiry.
  • On future requests: client sends the token back; server verifies signature + expiry.
  • A JWT is an ID card the server vouches for — not a secure storage container.

8. Foreign Keys & relationships

ForeignKey("subjects.id") tells the database "this column must reference a real row in the subjects table." relationship("Subject") is a Python-only convenience for accessing the related object directly.

9. Object-level authorization

Shallow (Subject, Skill, CareerGoal, Internship): user_id sits directly on the table. Nested (Assignment, Exam): ownership is checked through the parent Subject first. Skipping this is a real vulnerability class called broken object-level authorization (BOLA).

10. Vague login error messages

Both "email doesn't exist" and "wrong password" return the same generic 401 — prevents user enumeration attacks.

11. Enums for restricted values

Internship.status can only be applied / interview / selected / rejected — enforced at both the Pydantic layer and the database layer.

🔑 Habits worth keeping permanently

  1. Commit after every working feature — small, frequent commits beat one giant commit at the end.
  2. .env never goes to GitHub — always sanity-check before pushing.
  3. Read tracebacks from the bottom up.
  4. Case sensitivity matters everywhere in Python.
  5. After renaming a class/file/table, search for every place that name is referenced.
  6. Full restart > relying on --reload whenever structural changes are involved.
  7. create_all() is a learning-stage tool — switch to Alembic before the project gets much bigger.
  8. Never store plain passwords. Always hash. Non-negotiable, forever.
  9. Re-read new class/function names letter by letter before saving.
